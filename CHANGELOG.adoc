== Unreleased

=== Build & CI

* Quarantine lane for known-failing-on-master tests: `@Quarantined(reason, tracking, fixedBy)` removes a diagnosed failing test from the *gating* CI suites (so green checks mean mergeable) while a seconds-fast "Quarantine Audit" job enforces the registry + owner claims on every PR (fail-fast, no tests run) and the non-gating "Quarantine Lane / tests" job runs the lane on every PR push and every merge to master (+ dispatch), posts a sticky per-test report comment, and opens a merge-blocking review thread when a deterministic (non-`flapping`) quarantined test passes - the fix landed, so the annotation must be deleted, with an audit summary of each quarantined test and its owning fix PR. The live registry `docs/QUARANTINED_TESTS.md` is CI-enforced to match the annotations, and each entry's owner claim is verified against reality (owning fix PR must exist and be open; merged-but-still-quarantined or closed-unmerged owners turn the job red). Releases are blocked while any test is quarantined (`release.yml` guard; snapshots still publish). Locally: `bin/quarantined-test.sh`. First occupant: `PartitionStateCommittedOffsetIT.committedOffsetRemoved` (the `[latest]` nudge race, owned by https://github.com/astubbs/parallel-consumer/pull/80[#80]).
* The optional `local` self-hosted PR checks (`pr-local-fast-feedback.yml`) are disabled while that runner is offline — they showed as eternally-pending on every PR; manual dispatch still works, and re-enabling is a one-line trigger restore documented in the workflow.
* Optional, non-gating self-hosted fast-feedback lane on a high-CPU runner (`pr-highcpu-fast-feedback.yml`, `runs-on: [self-hosted, highcpu]`): unit / integration / performance / mutation run as a concurrent matrix, far faster than the 2-core GitHub-hosted gate. Same-repo-guarded (fork PRs never run on the self-hosted box) and `continue-on-error` + not required, so an offline runner never blocks a merge (the required gate stays GitHub-hosted; exception: the `Chaos Pain Suite` entry is deliberately NOT `continue-on-error` - a chaos RED is a real finding and shows red - though still not a required gate). Triggers on `pull_request` + `workflow_dispatch`. See link:docs/SELF_HOSTED_RUNNER.md[docs/SELF_HOSTED_RUNNER.md].
* Mutation testing (PIT) now also runs advisory on the GitHub-hosted PR build (`bin/ci-mutation-test.sh`), scoped to the core classes changed vs the PR base so it fits the 2-core runner. The highcpu lane runs two mutation jobs side by side (experimental): the same PR-scoped one and a full `internal.*` sweep (`PIT_FULL_SWEEP=true`).
* Chaos Pain Suite: seeded, replayable chaos scenarios (`@Tag("chaos")`, run with `-Dincluded.groups=chaos`, replay with `-Dchaos.seed=<long>`) driving PC fleets through churn storms under SLO probes (progress watermark, rebalance-dwell zombie detection, Class 2 committed-offset lag stagnation) with a no-loss/bounded-duplicates correctness ledger - calibrated detectors for the #857-family silent stalls. Never PR-gating: runs per same-repo PR commit (highcpu lane, check `highcpu / Chaos Pain Suite`) and on-demand with seed/reps (`chaos-pain.yml`) on the self-hosted highcpu runner, with a per-run timing summary.
* Ambient probe "flight recorder" for every broker integration test: a JUnit extension on `BrokerIntegrationTest` runs the chaos suite's ProgressProbe in observer mode under every IT - on test failure it logs an autopsy (rebalance-dwell + per-partition committed-offset stagnation + frozen-partition table) so generic timeouts arrive pre-diagnosed; silent on passing tests; opt-outs via `-Dambient.probe=off` or `@NoAmbientProbe`.
* The automated PR reviewer can now run the test suites itself (`claude-code-review.yml`): JDK 17 + Maven cache are set up, and `bin/ci-unit-test.sh` / `bin/ci-integration-test.sh` are granted via `--allowedTools`. The review fires on `pull_request` *before* the CI test jobs finish, so it could never read their results - it could only restate the author's claims. PR https://github.com/astubbs/parallel-consumer/pull/100[#100] showed why that matters: a regression test was named so surefire never collected it, and the suite was green precisely because the new test never ran. The reviewer is now also told to check which tests actually ran, not just the totals. Chaos stays out of reach (too slow for a review pass) and the job is capped at 30 minutes. **Blocking findings are now raised as inline review comments** rather than buried in the summary: the `master` ruleset requires review threads to be resolved before merge, so an inline thread is the only thing that actually gates a merge - a blocking finding written only in a PR-level comment can be merged straight past. Non-blocking notes stay in the summary, so routine observations don't become merge gates. The reviewer is also granted the repo's fast read-only verification scripts (`bin/check-*.sh`) so it can independently re-run what a PR claims - e.g. confirm a copyright-header or quarantine-registry claim - instead of inferring it from the diff (https://github.com/astubbs/parallel-consumer/pull/102[#102]).
* Test classes that CI silently never ran are now impossible to add: a new ArchUnit convention rule (`TestConventionRules`, applied per-module) fails the build when a class holding `@Test`/`@ParameterizedTest` methods is named something surefire's default includes (`Test*`, `*Test`, `*Tests`, `*TestCase`) do not match. Three such tests had been dormant on master - `MockConsumerTestWith{CommitTimeout,SaslAuthentication}Exception` and `MockConsumerTestWithEarlyClose`, two of which cover the commit-exception ladder - and have been renamed and re-enabled (all pass). Also fixes the `largeOffsetMap` flake at its source: `OffsetMapCodecManager`'s mutable static codec state was guarded by a one-sided lock, so the reading test could observe another test's forced codec; the reader now declares the same `@ResourceLock`. Also fixes a long-standing shutdown-commit flake in `ParallelEoSStreamProcessorTest` that waited on control-loop *cycles* for a commit driven by wall-clock - it now waits for the commit itself. That one test aborted the whole PIT mutation job whenever it flaked, since PIT fails when a test is unstable without mutation (https://github.com/astubbs/parallel-consumer/pull/101[#101]).
* PR checklist is now enforced: a single `.github/PULL_REQUEST_TEMPLATE.md` (deduplicated) with a `PR Checklist` CI gate (`pr-checklist.yml`) that, for human-authored PRs, fails when the checklist is missing entirely *or* when any box is left unchecked without an `N/A` reason - so changelog/docs/tests/title-body-sync don't get skipped. Only real bot authors (Dependabot/Renovate etc., GitHub user type `Bot`) are exempt; a human PR can no longer bypass the gate by simply dropping the template.

== 0.6.0.0

First release of the community fork of https://github.com/confluentinc/parallel-consumer[confluentinc/parallel-consumer] (upstream is no longer actively maintained). Drop-in compatible with upstream 0.5.x — the only required change is the Maven groupId (see Breaking below). Includes upstream fixes and features merged after upstream's last release (0.5.3.3) that were never published there.

=== Breaking

* Maven coordinates rebranded from `io.confluent.parallelconsumer` to `bz.stub.parallelconsumer` (https://github.com/astubbs/parallel-consumer/pull/55[#55]). Update your dependency declarations; the library API is otherwise unchanged from upstream.

=== Improvements

* The project is renamed to *Kafka Parallel Consumer* (README and branding). Java package names (`io.confluent.parallelconsumer.*`) are unchanged, so imports are unaffected — only the Maven groupId changed (see Breaking).
* feature: new `parallel-consumer-mutiny` module — SmallRye Mutiny (Quarkus) integration (upstream https://github.com/confluentinc/parallel-consumer/pull/891[#891]).
* Commit-failure error logging now includes the offsets being committed, to aid diagnosis of failed commits (upstream https://github.com/confluentinc/parallel-consumer/pull/850[#850]).
* Modernized CI (parallel unit/integration/performance suites, SpotBugs, PIT mutation testing, dependency scanning) and automated Maven Central publishing (https://github.com/astubbs/parallel-consumer/commit/b810e873[b810e873], https://github.com/astubbs/parallel-consumer/commit/2bcc74d9[2bcc74d9]).

=== Examples

* `parallel-consumer-example-streams`: `StreamsApp` now takes the Kafka `bootstrapServers` via its constructor (`new StreamsApp(bootstrapServers)`) instead of relying on subclass-and-override test hooks. The example is now runnable/configurable as shown - previously its consumer/producer/server methods were non-functional stubs (`new KafkaConsumer<>(new Properties())`, `"add your server here"`) that only the test filled in. `run()`, `close()`, and the input/output topic constants are now `public`.

=== Fixes

* fix: null epoch race condition in EpochAndRecordsMap - poll() returning records before onPartitionsAssigned() no longer causes NPE; records are safely skipped and re-delivered (https://github.com/astubbs/parallel-consumer/commit/afde8c5e[afde8c5e]; relates to upstream https://github.com/confluentinc/parallel-consumer/issues/326[#326])
* fix: `OffsetMapCodecManager` is kept instantiated so PC metrics are no longer recreated on every commit (upstream https://github.com/confluentinc/parallel-consumer/pull/892[#892]; relates to upstream https://github.com/confluentinc/parallel-consumer/issues/859[#859]).

=== Dependencies

* Dependencies and build plugins refreshed to their latest non-major versions (https://github.com/astubbs/parallel-consumer/pull/73[#73]): JUnit 5.10.2 → 5.14.4, Mockito 5.12.0 → 5.23.0, Testcontainers 1.19.8 → 1.21.4, AssertJ 3.24.2 → 3.27.7, SLF4J 2.0.13 → 2.0.18, Project Reactor 3.6.2 → 3.8.6, SmallRye Mutiny 2.9.4 → 2.9.5, Vert.x 4.5.7 → 4.5.31, Lombok 1.18.28 → 1.18.46, plus Guava, commons-lang3, Logback and the PostgreSQL driver.
* The Kafka client stays on **3.9.1** — Kafka 4.x (and the other majors JUnit 6, Testcontainers 2, Vert.x 5, Mutiny 3, WireMock 3) were deliberately deferred to keep the release low-risk. See link:docs/inflight.md[docs/inflight.md].

=== Build & CI

* New `Self-Hosted Tests` workflow runs the integration and performance suites on a self-hosted runner (a Proxmox Linux VM or a Mac), parallelised on real hardware where the `ci` profile runs them sequentially for GitHub's 2-core hosted runners. Integration runs in forked per-broker mode (`-DforkCount=4 -DreuseForks=true`, each JVM fork gets its own broker); performance uses in-JVM thread parallelism (`-Dparallel-tests=true`). Manual/scheduled only, never on PRs; the GitHub-hosted PR gate is unchanged. See link:docs/SELF_HOSTED_RUNNER.md[docs/SELF_HOSTED_RUNNER.md]. Replaces the earlier Windows-only performance workflow.
* The fast unit (surefire) suite now forks one JVM per core in CI (process-level parallelism), and an ArchUnit rule keeps Testcontainers / `BrokerIntegrationTest` tests out of it - they must live in an `integrationTests` package (run by failsafe, with Docker) - so the unit suite stays fast and can't be silently inflated by slow Docker-dependent tests.

== v0.3.0.0

=== Features

* Queueing and pressure system now self tuning, performance over default old tuning values (`softMaxNumberMessagesBeyondBaseCommitOffset` and `maxMessagesToQueue`) has doubled.
** These options have been removed from the system.
* Offset payload encoding back pressure system
** If the payload begins to take more than a certain threshold amount of the maximum available, no more messages will be brought in for processing, until the space need beings to reduce back below the threshold.
This is to try to prevent the situation where the payload is too large to fit at all, and must be dropped entirely.
** See Proper offset encoding back pressure system so that offset payloads can't ever be too large https://github.com/confluentinc/parallel-consumer/issues/47[#47]
** Messages that have failed to process, will always be allowed to retry, in order to reduce this pressure.

=== Improvements

* Default ordering mode is now `KEY` ordering (was `UNORDERED`).
** This is a better default as it's the safest mode yet high performing mode.
It maintains the partition ordering characteristic that all keys are processed in log order, yet for most use cases will be close to as fast as `UNORDERED` when the key space is large enough.
* https://github.com/confluentinc/parallel-consumer/issues/37[Support BitSet encoding lengths longer than Short.MAX_VALUE #37] - adds new serialisation formats that supports wider range of offsets - (32,767 vs 2,147,483,647) for both BitSet and run-length encoding.
* Commit modes have been renamed to make it clearer that they are periodic, not per message.
* Minor performance improvement, switching away from concurrent collections.

=== Fixes

* Maximum offset payload space increased to correctly not be inversely proportional to assigned partition quantity.
* Run-length encoding now supports compacted topics, plus other bug fixes as well as fixes to Bitset encoding.
